# Codex Assist 0.5.0

Codex Assist 0.5.0 reuses the Codex prompt cache, fixes a sign-out that a reload could cause during a token refresh, and makes device actions refuse malformed tool calls. It also removes the hidden Sources card data from search answers.

## Changes

- Reuse the Codex prompt cache. Every request now carries a stable session ID derived from the config entry. In live tests, about 97% of a typical Assist prompt came from the cache after the first command, including in new conversations. Token usage, including cached tokens, is logged at debug level for `custom_components.codex_assist.codex_client`. ([#80](https://github.com/itsreverence/ha-codex-assist/pull/80))
- Keep the token-refresh lock across config entry reloads. Before, reloading the integration while a request refreshed its token could reuse a rotated refresh token and require a new device sign-in. Options changes, reauthentication, and manual reloads could all trigger it. ([#76](https://github.com/itsreverence/ha-codex-assist/pull/76))
- Take tool calls only from completed output items, as Codex CLI does. A tool call without a call ID or name, with arguments that are not a JSON object, or with a repeated call ID now fails the turn instead of running. ([#77](https://github.com/itsreverence/ha-codex-assist/pull/77))
- Remove the Sources card and its citation plumbing. Search answers no longer include Sources data in `response.card`. Search results still reach the model and stay available for follow-up questions. ([#70](https://github.com/itsreverence/ha-codex-assist/pull/70))
- Put the first-run steps first in the README and correct HACS navigation and model-replacement guidance. ([#71](https://github.com/itsreverence/ha-codex-assist/pull/71))
- Remove unused client code, strengthen tests, and update dependencies. ([#72](https://github.com/itsreverence/ha-codex-assist/pull/72), [#73](https://github.com/itsreverence/ha-codex-assist/pull/73), [#74](https://github.com/itsreverence/ha-codex-assist/pull/74), [#75](https://github.com/itsreverence/ha-codex-assist/pull/75), [#78](https://github.com/itsreverence/ha-codex-assist/pull/78), [#79](https://github.com/itsreverence/ha-codex-assist/pull/79))

Thanks to [@Maeriberii](https://github.com/Maeriberii), whose fork's work on prompt caching and usage telemetry gave us the idea for #80.

## Updating

Update through HACS and restart Home Assistant. Existing sign-in, model selections, and prompts are preserved.

Apps or automations that read Sources data from `response.card` in conversation results will no longer receive it. The stock Home Assistant Assist UI did not display that data.

The Codex backend's caching behavior is not a public contract. If it stops honoring the session ID, requests still work without caching.

Fallback model suggestions remain unchanged after reviewing the [official model guidance](https://learn.chatgpt.com/docs/models) on October 27, 2026. Account discovery remains authoritative, and saved model selections are never replaced automatically.

Home Assistant 2026.6.0 remains the minimum. The downstream Codex service interface remains an undocumented, unstable dependency. Hosted search remains opt-in.
