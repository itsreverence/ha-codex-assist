# Codex Assist 0.4.9

This release improves authentication recovery, image attachment handling, and interrupted responses. It also protects configured prompts in diagnostic exports and avoids unnecessary sign-in during duplicate setup.

## Changes

- Diagnostics redact configured prompts from both entry data and options, alongside tokens. Stored configuration is unchanged. This protection does not apply to backups or general Home Assistant logs. ([#55](https://github.com/itsreverence/ha-codex-assist/pull/55))
- Adding a second integration entry stops before device-code sign-in. Reconfigure the existing entry to change accounts or reconnect. ([#58](https://github.com/itsreverence/ha-codex-assist/pull/58))
- Temporary authentication transport failures and malformed responses use the existing recovery paths. Saved credentials and cached model choices are preserved. A failed code exchange can still require restarting sign-in with a new code. ([#56](https://github.com/itsreverence/ha-codex-assist/pull/56))
- Unreadable or oversized selected images accompanying nonblank instructions fail explicitly before a model request. Images in discarded history are no longer read. Non-image attachments remain ignored. ([#57](https://github.com/itsreverence/ha-codex-assist/pull/57))
- Streaming responses must confirm completion before returning success or dispatching proposed tool calls. Interrupted images are not saved as successful results. Text may still stream before completion; already delivered text and earlier completed actions cannot be rolled back. ([#59](https://github.com/itsreverence/ha-codex-assist/pull/59))

## Updating

Update through HACS and restart Home Assistant. Existing sign-in and settings are preserved. Home Assistant 2026.6.0 remains the minimum supported version.

If an image request now fails where it previously returned an answer, check that every selected image is readable and within the existing limits: four images, 10 MiB per image, and 20 MiB total. Previous versions could silently omit an unusable image.

Device actions now wait for the backend response to finish. An incomplete response reports a failure instead of dispatching its proposed actions. Authentication retries remain limited to the existing policy and do not replay text or tool output already delivered by that invocation.

Fallback model suggestions remain unchanged after reviewing the [official model guidance](https://learn.chatgpt.com/docs/models) on October 14, 2026. Account discovery remains authoritative; saved model selections are never replaced automatically.
