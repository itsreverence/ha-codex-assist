# Codex Assist 0.4.10

Codex Assist 0.4.10 improves streamed answers, clarification follow-ups, and conversation error handling.

## Changes

- Recover missing answer text from completed assistant messages when the stream can be reconciled safely. Reject silent responses and ambiguous or conflicting text instead of reporting success. Failed conversation results omit the Sources card. ([#66](https://github.com/itsreverence/ha-codex-assist/pull/66))
- Preserve authentication and account-limit classifications in streamed backend failures. ([#65](https://github.com/itsreverence/ha-codex-assist/pull/65))
- Ask the model to end needed clarification replies with one concise question so Home Assistant can apply its native follow-up behavior. Saved prompts remain unchanged. ([#68](https://github.com/itsreverence/ha-codex-assist/pull/68))
- Use fixed, short speech for caught conversation failures. Logs retain the failure stage, exception class, recovery decisions, and integration filename and line without raw exception messages or formatted tracebacks. AI Task error behavior is unchanged. ([#67](https://github.com/itsreverence/ha-codex-assist/pull/67))
- Make hosted-search probes reject incomplete responses and update CI actions. ([#64](https://github.com/itsreverence/ha-codex-assist/pull/64), [#61](https://github.com/itsreverence/ha-codex-assist/pull/61))

## Updating

Update through HACS and restart Home Assistant. Existing sign-in, model selections, and prompts are preserved.

Clarification guidance is a model instruction, not an execution guard or a guarantee that a satellite microphone reopens. Tested Home Assistant versions recognize final `?`, ASCII `;` (U+003B), and fullwidth `？` for continuation. Other punctuation, such as Arabic `؟`, does not trigger that native check. Physical ESPHome satellite behavior still needs reporter confirmation after release in [issue #62](https://github.com/itsreverence/ha-codex-assist/issues/62).

The conversation error boundary addresses [issue #63](https://github.com/itsreverence/ha-codex-assist/issues/63) for caught integration failures. Model-generated text, already streamed text, tool-result details, and framework-owned errors can still contain diagnostics. This release does not guarantee secrecy across every Home Assistant log or trace.

Error speech is now generic, and conversation failure logs contain less detail. Include your Home Assistant and integration versions, the log `stage`, `exception`, and `location` fields, and reproduction steps in bug reports. Review logs for private data before sharing them.

Fallback model suggestions remain unchanged after reviewing the [official model guidance](https://learn.chatgpt.com/docs/models) on October 15, 2026. Account discovery remains authoritative, and saved model selections are never replaced automatically.

Home Assistant 2026.6.0 remains the minimum. The downstream Codex service interface remains an undocumented, unstable dependency. Hosted search remains opt-in.
