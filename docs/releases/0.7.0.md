# Codex Assist 0.7.0

Codex Assist 0.7.0 lets each conversation agent choose which of Home Assistant's LLM APIs it may use. You can now give an agent Home Assistant's own diagnostics and management tools, or tools from MCP servers, alongside or instead of Assist device control. Existing agents keep exactly the tools they had.

## Changes

- Choose each conversation agent's tools under **Advanced chat settings → Home Assistant tools**. The list shows every LLM API Home Assistant has registered: **Device control** (Assist), the admin-only **Home Assistant** API on Home Assistant 2026.11 and newer, and each MCP server connected through Home Assistant's MCP integration. Clear every choice for a chat-only agent. ([#91](https://github.com/itsreverence/ha-codex-assist/pull/91))
- Home Assistant still merges the selected APIs, checks admin-only access, and runs every tool call. Codex Assist adds no service-call path of its own. ([#91](https://github.com/itsreverence/ha-codex-assist/pull/91))
- Leave out tools Codex cannot call. That covers names outside letters, digits, `_` and `-` (up to 64 characters), and a tool named `web_search` while hosted web search is on, so it cannot shadow the hosted search tool. Each skipped tool is logged at debug level. ([#91](https://github.com/itsreverence/ha-codex-assist/pull/91))
- Keep a saved tool choice whose integration is unloaded, labelled "saved; not currently available", until you clear it. ([#91](https://github.com/itsreverence/ha-codex-assist/pull/91))

Thanks to [andrzejf1994](https://github.com/andrzejf1994) for the detailed proposal in [#90](https://github.com/itsreverence/ha-codex-assist/issues/90) that this follows, and to [djevrek](https://github.com/djevrek) for describing the voice-control use case.

## Safety

With the default **Device control** tools, the safety boundary is unchanged. The agent reaches only the entities you expose to Assist.

An agent you give the **Home Assistant** API can read your whole system, including entities you have not exposed, and run any Home Assistant action. Home Assistant refuses that API when no admin user made the request, which is the case for most voice satellites. An agent you give an MCP server can use whatever that server offers, and the results go to Codex. Give these to a separate agent rather than your everyday voice agent.

## Updating

Take a full Home Assistant backup before you update. Update through the Marketplace (Home Assistant 2026.11 and newer) or HACS, then restart Home Assistant. Your agents and their settings carry over, and you do not need to sign in again. Coming from 0.5.0 or earlier, the update also moves your settings into the 0.6.0 per-agent layout, which older releases cannot load.

AI Task entities are unchanged and still offer Codex no Home Assistant tools.

Home Assistant 2026.6.0 remains the minimum. The admin-only **Home Assistant** API needs Home Assistant 2026.11. The downstream Codex service interface remains an undocumented, unstable dependency. Hosted search remains opt-in.
